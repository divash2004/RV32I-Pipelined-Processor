10.1 Purpose

In a pipelined processor, multiple instructions execute simultaneously in different pipeline stages. This overlap can introduce situations where an instruction cannot proceed correctly because the required data or resources are unavailable. The Hazard Handling Unit ensures correct program execution by detecting and resolving such hazards while minimizing performance penalties.

10.3 Forwarding Unit

Purpose
The Forwarding Unit eliminates unnecessary pipeline stalls by supplying the most recent result directly from later pipeline stages instead of waiting for register write-back.

10.7 Design Decisions

Why use forwarding?
Without forwarding, almost every dependent ALU instruction would require pipeline stalls, significantly reducing throughput.

Why is load-use still stalled?
Forwarding cannot provide data before the memory access has completed. Since the loaded value becomes available only after the MEM stage, one pipeline bubble is unavoidable.

Why no branch prediction?
The project prioritizes architectural clarity and modular RTL over aggressive performance optimization. Branch prediction would substantially increase design complexity while contributing little to the educational objectives.

Why are structural hazards eliminated instead of stalled?
Using separate instruction and data memories removes contention for memory access, simplifying the hazard handling logic and improving pipeline throughput.

Which hazards exist in your processor?
The processor encounters data hazards and control hazards. Structural hazards are eliminated through the Harvard memory architecture.

Why can't forwarding solve a load-use hazard?
The result of a load instruction is produced only after the memory access completes in the MEM stage. The following instruction requires the operand at the beginning of the EX stage, one cycle earlier than the data becomes available. Consequently, a single-cycle stall is unavoidable.

Why is forwarding possible for ALU instructions?
The ALU result is available at the end of the Execute stage and can be forwarded directly to the next instruction without waiting for register write-back.

Why are only IF and ID stalled during a load-use hazard?
The load instruction already in EX must continue progressing to complete the memory access. Stalling the younger instructions while allowing the load to advance inserts exactly one pipeline bubble and preserves correct execution.

Why do you flush IF/ID and ID/EX instead of EX/MEM?
When a branch is resolved in EX, the instructions in IF and ID belong to the wrong control path and must be discarded. Instructions in MEM and WB are older than the branch and therefore belong to the correct execution path.
