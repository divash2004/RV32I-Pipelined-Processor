9.1 Purpose

The Branch Unit is responsible for evaluating branch conditions and generating PC-relative target addresses. It operates during the Execute stage and consists of three independent functional units: a Comparator, Branch Target Adder, PC Control Logic.
Arithmetic execution and control-flow execution are implemented using separate hardware resources, Our processor deliberately separates these functions into three execution resources:
1) ALU 2) Comparator 3) Branch Target Adder
Whenever the next Program Counter differs from the sequential value (PC + 4), a flush request is asserted. The IF/ID and ID/EX pipeline registers are flushed so that instruction fetching resumes from the correct target address.

Chapter is describing the hardware responsible for control-flow execution, which consists of:

Comparator (EX stage) – evaluates the branch condition.
Branch Target Adder (EX stage) – computes PC + Immediate.
Next-PC Multiplexer (IF stage) – selects the next program counter.

Although referred to collectively as the Branch Unit, the control-flow hardware is distributed across the pipeline. The Execute stage performs branch evaluation and target address generation, while the Instruction Fetch stage updates the Program Counter by selecting the appropriate next PC through a multiplexer.

9.7 Next PC Selection (for PC mux)
The PC selection logic chooses between four possible values.

Condition			Next PC
000 (Normal)			PC + 4
001–100 (Branch taken)		Branch Target Adder Output
001–100 (Branch not taken)	PC + 4
101 (JAL)			Branch Target Adder Output
110 (JALR)			ALU Result

9.8 Design Decisions

Why use a dedicated comparator?
Decision
Branch comparisons are performed by a dedicated comparator rather than the ALU.
Why?
Branch comparison is logically independent of arithmetic operations. A dedicated comparator simplifies ALU design and separates arithmetic from control-flow evaluation.
Trade-off
Additional combinational hardware.

Why use a dedicated Branch Target Adder?
Decision
Target addresses for PC-relative branches and jumps are computed using a dedicated adder.
Why?
Target address calculation is independent of arithmetic instructions. A dedicated adder allows branch target computation without overloading the ALU.
Trade-off
Slight increase in hardware area.

Why is JALR handled differently?
Decision
JALR target addresses are computed by the ALU.
Why?
Unlike branches and JAL, JALR uses a register value (RS1) instead of the current program counter as the base address. Since the ALU already supports base-plus-offset addition, no additional hardware is required.JAL computes its target as PC + Immediate, which matches the Branch Target Adder's function. JALR computes its target as RS1 + Immediate

Why are branches resolved in the Execute stage?
Decision
All branch decisions are completed during the Execute stage.
Why?
Both the comparison result and the target address become available in EX. Resolving branches earlier would require moving comparison hardware into Decode, while resolving them later would unnecessarily increase the branch penalty.

What happens when a branch is taken?
The comparator asserts BRANCH_TAKEN, the PC multiplexer selects the branch target address, and the younger instructions in the IF and ID stages are flushed. Instructions already in EX, MEM, and WB continue normally.

Why doesn't the Branch Unit write to the register file?
The Branch Unit only determines control flow. Register updates for JAL and JALR are performed through the normal write-back path using PC+4, while ordinary branch instructions do not produce a register result.
