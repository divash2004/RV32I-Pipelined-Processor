11.1 Purpose

The Memory System provides instruction storage and data storage for the processor. A Harvard architecture is adopted, using separate instruction and data memories to eliminate structural hazards between instruction fetch and data access.

11.2 Memory Organization

completely independent memories
independent address buses
independent data buses

Completely Independent Memories
There are two separate memories:
Instruction Memory stores program instructions.
Data Memory stores variables and other data.                                                           
Since they are separate, accessing one does not affect the other.

Independent Address Buses
An address bus carries the address of the memory location to be accessed.
Harvard architecture has:
One address bus for Instruction Memory.
Another address bus for Data Memory.
This allows the CPU to send instruction and data addresses at the same time.

Independent Data Buses
A data bus transfers data between the CPU and memory.
There are two separate data buses:
One transfers instructions from Instruction Memory to the CPU.
The other transfers data between Data Memory and the CPU.
Both transfers can occur simultaneously.

11.7 Design Decisions

Why no cache?
The processor is intended as an educational RTL implementation. Introducing caches would significantly increase design complexity while obscuring the core pipeline concepts.

Why single-cycle memories?
Ideal single-cycle memories simplify pipeline timing and allow the project to focus on datapath and control logic rather than memory latency.

Why only word accesses?
The implemented ISA subset contains only LW and SW. Supporting byte and halfword accesses would require additional alignment logic, byte-enable circuitry, and sign/zero extension, none of which introduce fundamentally new architectural concepts for this project.
